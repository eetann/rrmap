# タスクファイルのフォーマット

各タスクは、フロントマター付きのMarkdownファイル1つとして管理する。

## フロントマター

```yaml
---
id: TASK-0001
title: データモデル・ファイル設計
status: draft
parent: null
milestone: null
---
```

- `id`: タスクの一意なID。`TASK-`+ゼロ埋め連番（例: `TASK-0001`）
- `title`: タスクのタイトル
- `status`: タスクの状態。以下のいずれか
  - `draft`: とりあえず雑に書いた
  - `refined`: 実装の複雑さを考えてちゃんと書いた（タスクを分割した場合、分割元の親タスクはこの状態になる）
  - `in_progress`: 実装中
  - `done`: 実装済み
  - `cancelled`: 中止
- `parent`: 分割元の親タスクのid（`TASK-0001`の形式）。トップレベルのタスクは`null`
  - 親子関係は1階層のみ。`parent`を持つタスク（子タスク）はさらに子タスクを持てない
  - 子タスクの一覧は、`parent`が自分のidと一致するタスクファイルを逆引きして求める（親側にリストは持たせない）
- `milestone`: 所属するマイルストーンのid。どのマイルストーンにも属さないタスクは`null`（[milestone-format.md](./milestone-format.md)参照）
  - 組み込みの`MILESTONE-ARCHIVED`も指定できる。片付いたタスクの置き場で、一覧から外れる

## 並び順

タスクの表示順は、`.rrmap/tasks/order.json`にidの配列として持つ。並び順はタスク同士の関係なので、個々のファイルではなく1ファイルにまとめている。

```json
[
  "TASK-0003",
  "TASK-0001"
]
```

- 前から順に並べる。ここに載っていないタスク（新しく作ったものなど）はid順で後ろに置く
- ファイルがなくてもよい。その場合は全体がid順になる
- 手で書き換えてもよい。実在しないidや重複は読み込み時に無視する
- マイルストーンをまたいだ1本の配列で持つ。マイルストーンごとの並びは、この配列から所属するタスクを抜き出したものとして扱う（タスクの`milestone`を変えても並び順を作り直さずに済む）
- 子タスクは親タスクの直下に表示されるので、この配列での位置に関わらず親についていく。同じ親を持つ子タスク同士の並びは、この配列の順になる

## 本文

自由なMarkdown。CLI/UIは本文の構造をパースせず、そのまま表示・編集の対象にする。

テンプレートは強制しないが、「何をするか」「現在の状態」「方針・意思決定」あたりに触れておくと後から見返しやすい（あくまで目安）。
