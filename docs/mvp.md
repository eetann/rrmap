# MVP
## 問題

AIと一緒に開発すると、最初は人間が雑に書いたロードマップをもとに作業を進められる一方、開発が進むにつれてタスクの粒度や内容が変化する。

また、タスクについて「どう実装することにしたか」という小さな意思決定が発生するが、それらはADRにするほど重要ではないため、現在はロードマップに追記され、タスクの計画と意思決定が混在しやすい。

さらに、ロードマップを単一ファイルで管理すると、完了したタスクが蓄積してAI・人間双方にとって扱いづらくなる。

## 解決したいこと

人間が雑に作り始めたロードマップを、AIと一緒に開発の進行に合わせて整理・具体化できるようにする。

ロードマップはタスク単位で管理し、各タスクについて、

何をするのか
現在どういう状態なのか
そのタスクについてどういう方針・意思決定をしたのか

を残せるようにする。

一方、開発を通じて得られた一般的な知識や制約、ハマりどころなどはロードマップには蓄積せず、Skillの判断によって適切なKnowledgeドキュメントとして別途残す。

ADRやユーザー向けドキュメントなど、既に役割が確立しているドキュメントは既存の仕組みを利用する。
