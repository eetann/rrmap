# マイルストーンファイルのフォーマット

各マイルストーンは、フロントマター付きのMarkdownファイル1つとして管理する。タスクと同様、CLI経由での作成・編集を基本としつつ、直接編集された場合でもCLIが正しく読み込めるようにする（[task-format.md](./task-format.md)参照）。

## フロントマター

```yaml
---
id: MILESTONE-0001
title: マイルストーン管理の仕組み
status: planned
hidden: false
---
```

- `id`: マイルストーンの一意なID。`MILESTONE-`+ゼロ埋め連番（例: `MILESTONE-0001`）
  - タスクのid（[task-format.md](./task-format.md)参照）と見分けやすくするため、`MILESTONE-`のprefixを付けている
- `title`: マイルストーンのタイトル
- `status`: マイルストーンの状態。以下のいずれか
  - `planned`: まだ着手していない
  - `active`: 進行中
  - `completed`: 完了
- `hidden`: `true`にするとWeb UIのタスク一覧から外れる（サイドバーの「非表示のマイルストーン」からは開ける）。省略時は`false`

## 組み込みマイルストーン

`MILESTONE-ARCHIVED`はrrmapが用意する組み込みのマイルストーンで、対応するファイルは存在しない。片付けておきたいタスクの置き場として、タスク側の`milestone`に指定できる。

- `hidden: true`のマイルストーンと同じ扱いになり、Web UIのタスク一覧には出ない
- ファイルを持たないので、このidのファイルを作ることも、タイトル・ステータス・本文を編集することもできない
- 一覧・詳細の取得や、タスクの所属先としての指定は通常のマイルストーンと同じように扱える

## 本文

自由なMarkdown。CLI/UIは本文の構造をパースせず、そのまま表示・編集の対象にする。

目的・スコープなど、マイルストーンについて残しておきたいことを書く（あくまで目安、テンプレートは強制しない）。

## タスクとの関連付け

タスク側のフロントマターに`milestone`フィールドを持たせ、所属するマイルストーンのidを指定する（[task-format.md](./task-format.md)参照）。マイルストーン側はタスクの一覧を持たず、タスク側の`milestone`を逆引きして求める（`parent`と同様の考え方）。
