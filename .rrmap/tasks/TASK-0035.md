コミットの対象は`.rrmap/`配下に固定した。コードを書きながらタスクのステータスも動かすことが多く、`git add -A`だと両方が1つのコミットに入ってしまうため。ステージとコミットの両方にパスを渡している。ほかに編集中のファイルやステージ済みの変更があっても巻き込まない。

ハマりどころ: `git commit -- <path>`は追跡済みのファイルしか見ない。新しく作ったタスクファイルは、これだけでは入らない。かといって`git add`だけで済ませると、今度は`.rrmap/`の外のステージ済みの変更まで一緒にコミットされてしまう。両方要る。

コミットメッセージは変更内容から組み立てる。1件ならid、複数なら件数に丸める(`add TASK-0042, update 3 tasks`)。あとからgit logを眺めたときに、どのタスクが動いたかを追える粒度にしたかった。
