## 何をするか

Web UI（`src/web/server.ts`）を、rrmap自身のソースを含まないディレクトリをカレントディレクトリにして起動すると、TailwindのユーティリティクラスがまったくCSSに生成されず、スタイルの当たっていない素のHTMLになってしまう。これを直す。

## 現在の状態（README用のデモスクリーンショットを撮る過程で発覚）

- `bun-plugin-tailwind`は明示的な`@source`指定がないため、コンテンツスキャンの基点が起動時の`process.cwd()`に依存しているらしい
- 検証: `demo/`（rrmap自身のソースを含まない、タスクデータのみの空ディレクトリ）をcwdにして`bun --hot src/web/server.ts`を起動すると、生成されるCSSに`@layer utilities`の中身が空になる（theme変数とbaseレイヤーのみ）。リポジトリルートをcwdにすると正しく生成される
- rrmapは「管理したいプロジェクトのルートで`.rrmap/`を使う」設計（[docs/directory-structure.md](../../docs/directory-structure.md)）なので、これはまさに本来の使い方で起きる

## 方針・意思決定

- 根本原因は`@source`の話ではなく、`bunfig.toml`の探索だった。`bun --help`によると`-c, --config`のデフォルトは`$cwd/bunfig.toml`で、Bunは親ディレクトリを遡ってbunfig.tomlを探してくれない。そのため管理対象プロジェクト（rrmap自身のソースを含まないディレクトリ）をcwdにして起動すると`[serve.static] plugins = ["bun-plugin-tailwind"]`が読み込まれず、`bun-plugin-tailwind`自体がロードされない（`setup()`すら呼ばれない）ことをデバッグログで確認した。プラグインがロードされないと`.css`へのonLoadフックが登録されず、`@import "tailwindcss"`はただのCSS結合として扱われ、`@layer utilities { @tailwind utilities; }`のような未処理のat-ruleがそのまま出力される
- `@source`ディレクティブの追加も試したが、効果があったのは`--config`側の修正のみだった（`--config`でbunfig.tomlを明示すると`build.config.root`がbunfig.tomlのあるディレクトリになり、コンテンツスキャンの基点もcwd非依存になるため）。なので`styles.css`側の変更は不要と判断し、加えていない
- 対処は[TASK-0008](TASK-0008.md)で実装した`rrmap web`コマンド側で行う。CLIから`bun --config=<rrmap自身のbunfig.tomlの絶対パス> <rrmap自身のsrc/web/server.tsの絶対パス>`を子プロセスとして起動することで、cwdは呼び出し元のまま維持しつつ、正しいbunfig.tomlを強制的に読ませる
- `bun --config <path> <script>`のようにスペース区切りで書くと`<path>`の後の`<script>`が飲み込まれず変な挙動になる（`--config`の値として`<script>`が食われ、その後の引数が実行対象として解釈されない）。`--config=<path>`のイコール結合が必須
