## 何をするか

Web UI（`src/web/server.ts`）は、rrmap自身のソースを含まないディレクトリをカレントディレクトリにして起動すると、Tailwindのユーティリティクラスが一切CSSに生成されない。スタイルの当たっていない素のHTMLになってしまうこの問題を直す。

## 現在の状態（README用のデモスクリーンショットを撮る過程で発覚）

- `bun-plugin-tailwind`は明示的な`@source`指定がないため、コンテンツスキャンの基点が起動時の`process.cwd()`に依存しているらしい
- 検証: `demo/`（rrmap自身のソースを含まない、タスクデータのみの空ディレクトリ）をcwdにして`bun --hot src/web/server.ts`を起動すると、生成されるCSSに`@layer utilities`の中身が空になる（theme変数とbaseレイヤーのみ）。リポジトリルートをcwdにすると正しく生成される
- rrmapは「管理したいプロジェクトのルートで`.rrmap/`を使う」設計（[docs/directory-structure.md](../../docs/directory-structure.md)）なので、これはまさに本来の使い方で起きる

## 方針・意思決定

原因は`@source`の指定不足ではなく、`bunfig.toml`の探索方法にあった。`bun --help`によると`-c, --config`のデフォルトは`$cwd/bunfig.toml`で、Bunは親ディレクトリを遡ってbunfig.tomlを探してくれない。そのため、rrmap自身のソースを含まない管理対象プロジェクトをcwdにして起動すると、`[serve.static] plugins = ["bun-plugin-tailwind"]`の設定自体が読み込まれず、`bun-plugin-tailwind`がロードされない。実際にデバッグログを仕込んで確認すると、プラグインの`setup()`すら呼ばれていなかった。プラグインがロードされなければ`.css`へのonLoadフックも登録されず、`@import "tailwindcss"`はただのCSS結合として扱われ、`@layer utilities { @tailwind utilities; }`のような未処理のat-ruleがそのまま出力されていた。

`@source`ディレクティブの追加も試したが、効いたのは`--config`側の修正だけだった。`--config`でbunfig.tomlを明示すると`build.config.root`がbunfig.tomlのあるディレクトリになり、コンテンツスキャンの基点もcwdに依存しなくなる。そのため`styles.css`側の変更は不要と判断し、加えていない。

対処は[TASK-0008](TASK-0008.md)で実装した`rrmap web`コマンド側で行った。CLIから`bun --config=<rrmap自身のbunfig.tomlの絶対パス> <rrmap自身のsrc/web/server.tsの絶対パス>`を子プロセスとして起動し、cwdは呼び出し元のまま維持しつつ、正しいbunfig.tomlを強制的に読ませている。

なお`bun --config <path> <script>`とスペース区切りで書くと、`<path>`の後に続く`<script>`が`--config`の値として飲み込まれ、意図した通りに実行されない。`--config=<path>`のイコール結合が必須。
